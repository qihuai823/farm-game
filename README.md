# 农场游戏（Farm Game）

一个跑在浏览器里的星露谷式农场经营游戏。Phaser 3 + Vite，原生 JavaScript，零后端。

包含完整的种田循环、种子商店、背包、钓鱼小游戏、昼夜系统和本地存档。

---

## 快速开始

```bash
npm install
npm run dev        # 然后浏览器打开 http://127.0.0.1:5173
```

构建可部署版本：

```bash
npm run build          # 输出到 dist/，零版权风险，可直接公开部署
```

跑测试：

```bash
npm test
```

## 玩法

- **种田**：锄地 → 播种 → 浇水 → 收获。作物只有浇过水的那天才会生长，忘了浇水就白等一天
- **时间**：06:00 到次日 02:00，约 4 分钟一个游戏日。到点不睡会昏倒
- **体力**：锄地 2 点、浇水 1 点。体力见底就没法干活，睡觉恢复
- **经济**：收获的作物出货换金币，金币买更好的种子
- **钓鱼**：蓄力抛竿 → 等鱼咬钩 → 绿条追鱼小游戏。4 种鱼，越稀有越难钓也越值钱

操作：`WASD` 移动 · `1`-`5` 切换工具（锄头/水壶/种子/手/钓竿）· `空格` 使用 · `Tab` 背包 · `Q` 换种子

## 技术栈

| | |
|---|---|
| 渲染 | Phaser 3（WebGL，像素画模式）|
| 构建 | Vite |
| 语言 | 原生 JavaScript（ESM），不用 TypeScript |
| 依赖 | 运行时只有 Phaser 一个 |
| 测试 | 自研的零依赖检查脚本 + 断言 |

**为什么用 Phaser 3 而不是 4**：这个项目是 AI 辅助编写的，Phaser 3 的 API 在训练数据里覆盖充分，生成的代码报错明显更少。项目稳定后再迁移成本也不高。

## 架构设计

### 1. 贴图 key 就是接口 —— 素材可整体替换

游戏的每个视觉对象只通过**贴图 key** 引用资源（`'tree'`、`'player-down-0'`），不关心图从哪来。
换美术风格只需要两步：提供一张图源 + 改一份 `pack.map.json`（哪些区域对应哪些 key）。**业务代码一行不动。**

而且回退是**逐个 key** 的：映射表填了几个就用几个真素材，没填的用代码生成的占位图。所以可以渐进替换，不用一次性做完。

**尺寸也跟着素材包走**（`src/systems/PackSizes.js`）。不同素材包的物件尺寸天生不一样——星露谷的房子是 144×144，CC0 的只有 80×80。像素画非整数缩放会糊，所以不做缩放，而是让**几何跟着素材包变**：房子多大就占几格，门的位置、出货箱和商店的摆放全从尺寸推导。

### 2. 内容数据化

作物、鱼、价格、生长天数全在 `src/data/*.json` 里。加一种作物 = 在 JSON 里加一条，**不改代码**。
配套有自动校验（卖价必须高于种子价、复收间隔必须短于首次成熟天数等），改错了测试会挡住。

### 3. 纯逻辑与渲染分离

关键规则都写成不依赖 Phaser 的纯函数（`src/systems/`）。最典型的是钓鱼小游戏：
整套数学（鱼怎么游、绿条怎么动、进度怎么算）能在 Node 里跑，测试会**模拟 200 局"完美玩家"和"摆烂玩家"**，
断言"每种鱼都钓得上来"且"不动手就钓不上来"——防止调参数时把游戏调成不可玩。

### 4. 分层地图

- `ground` 层：走 Phaser tilemap，只有水有碰撞
- `objects` 层：走独立精灵 + 不可见碰撞盒

这样才做得出**深度排序**——人物可以走到树后面。碰撞形状和贴图完全解耦，换成不规则素材也不用改碰撞逻辑。

### 5. 四道自动化检查

`npm test` 会跑完（不会因为前面失败就短路）：

| 检查 | 抓什么 |
|---|---|
| `check-imports` | 用了某个名字但忘记 import（构建期不报错、运行时崩）|
| `check-html` | 内联 `<script>` 的语法错误（不走打包流程，容易漏）|
| `check-assets` | 贴图契约和代码是否一致、素材映射表是否完整/尺寸对不对 |
| `logic-test` | 140 项逻辑断言 |

前两个是**自研的零依赖脚本**，为的是补上构建期抓不到、但只有打开浏览器才暴露的那类错误。

## 素材与授权

这是这个项目比较特别的一块。

**仓库里同时准备了两套素材包：**

| 包 | 授权 | 位置 | 能否公开 |
|---|---|---|---|
| **CC0**（Ninja Adventure）| CC0-1.0 公共领域 | `public/cc0/` | ✅ 可商用、可公开、无需署名 |
| 星露谷 | 受版权保护 | `personal/` | ❌ 仅限本地自用 |

**默认使用 CC0 包**，所以 `npm run build` 的产物可以安全地传到 GitHub 或部署上线。

**为什么把个人用的素材放在 `public/` 之外**：Vite 只复制 `public/`，素材一旦不在里面，**干净构建在结构上就不可能带上它们**——不需要任何"构建后删除"的补救动作。事后清理依赖人记得执行，结构隔离是恒真的。

开发期用星露谷素材是为了最快验证布局和手感，但交付版本换成了 CC0。发布前可以跑 `npm run check:copyright` 确认产物干净。

**一句话**：素材可以换，但需要连几何一起换；版权风险靠架构隔离而不是靠人工检查。

## 目录结构

```
src/
  config.js          所有可调参数（速度/时间流速/地图大小）
  main.js            启动（含容器尺寸守卫）
  mapData.js         地图生成 + 地标推导
  textures.js        占位图生成（唯一需要"换掉"的文件）
  textures.pack.js   从图集切图（素材模式的运行时）
  data/              内容表（crops.json / fish.json）+ 素材映射表
  systems/           纯逻辑：时间/农田/商店/钓鱼/素材尺寸
  entities/          玩家
  scenes/            Boot / Farm / UI / Menu / Fishing
scripts/             检查和素材处理的命令行工具
public/cc0/          CC0 素材（可公开）
personal/            个人用途的素材（不进仓库、不进构建产物）
```

---

## 已知限制

- **没有季节系统** —— 天数无限累加（有意为之，先做农场核心循环）
- **只有 3 种作物、4 种鱼** —— 内容量刻意收窄，架构上加到几十种只需改 JSON
- CC0 素材包缺作物和鱼的图，这部分目前用代码生成的占位图
- 没有音效、没有手机端适配
- 单人单机，存档在 localStorage
